Mobi подключает движок Go к KGS, чтобы он мог воспроизводиться автоматически. Вы запускаете клиент в терминале и управляете им через файл конфигурации TOML или параметры командной строки. Установите и настройте свой движок отдельно; клиент обрабатывает вход в систему, поиск игр, ходов, часов и подсчета очков.

Переходите с клиента Java `kgsGtp.jar`? Начните с [руководства по обновлению]({% include page-url.html key='mobi/upgrade-guide' %}).

В этом руководстве рассматриваются Windows и Linux. Разверните раздел вашей операционной системы, чтобы увидеть команды PowerShell или Bash. Запустите примеры упакованных клиентов из извлеченного каталога клиента.

## Первая игра {#first-game}

Вам потребуется зарегистрированная учетная запись KGS, движок GTP версии 2, а также любые файлы конфигурации и модели, которые требуются движку. Перед запуском бота создайте учетную запись с помощью обычного клиента KGS. Для игры Ranked требуется дополнительное разрешение сервера; начните с игры Free.

Извлеките клиентский пакет для вашей операционной системы и архитектуры. Предоставляются пакеты для Windows и Linux для x64 и ARM64, включая среду выполнения .NET. Сохраните извлеченные файлы вместе. Исполняемый файл: `Kgs.Gtp.exe` для Windows и `Kgs.Gtp` для Linux.

### 1. Создайте свою конфигурацию {#1-create-your-configuration}

Скопируйте включенный [bot.example.toml]({{ '/mobi/bot.example.toml' | relative_url }}) в `bot.toml`:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
Copy-Item .\bot.example.toml .\bot.toml
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
cp ./bot.example.toml ./bot.toml
chmod +x ./Kgs.Gtp
```

</details>

Отредактируйте `account.username`, `engine.executable` и `engine.arguments`. Например:

<details markdown="1">
<summary>Windows</summary>

```toml
[account]
username = "YourBot"

[engine]
executable = 'C:\Go\katago.exe'
arguments = ["gtp", "-config", 'C:\Go\gtp.cfg', "-model", 'C:\Go\model.bin.gz']
```

</details>

<details markdown="1">
<summary>Linux</summary>

```toml
[account]
username = "YourBot"

[engine]
executable = "/opt/katago/katago"
arguments = ["gtp", "-config", "/srv/go/gtp.cfg", "-model", "/srv/go/model.bin.gz"]
```

</details>

Укажите пути и аргументы, необходимые вашему движку для входа в режим GTP. Каждый элемент массива представляет собой один аргумент; путь, содержащий пробелы, по-прежнему является одним элементом.

В примере выбран автоматический матч Free против людей, быстрая или средняя скорость и непрерывная игра. Установите для `automatch.rank` соответствующую оценку между `30k` и `1k`, если учетная запись не имеет числового ранга. KGS использует ранг учетной записи, если он доступен. При первом запуске команда ниже ограничивает игру одной игрой.

### 2. Проверьте двигатель {#2-check-the-engine}

Из извлеченного каталога клиента запустите:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
.\Kgs.Gtp.exe --config .\bot.toml --probe
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
./Kgs.Gtp --config ./bot.toml --probe
```

</details>

Клиент печатает имя механизма, версию и поддерживаемые команды, а затем завершает работу. Для этого не требуются учетные данные KGS, и он не подключается к KGS. Он проверяет обнаружение GTP; дополнительные правила, проверки часов, гандикапа и подсчета очков запускаются при запуске настроенного игрового режима.

### 3. Введите пароль и играйте {#3-supply-the-password-and-play}

Пароль берется только из переменной среды `KGS_PASSWORD`:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
$env:KGS_PASSWORD = '<account password>'
.\Kgs.Gtp.exe --config .\bot.toml --games 1
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
read -r -s -p 'KGS password: ' KGS_PASSWORD
export KGS_PASSWORD
printf '\n'
./Kgs.Gtp --config ./bot.toml --games 1
```

</details>

Найдите `Logged in to KGS`, затем `Game ready`. Клиент играет и автоматически засчитывает игру. `Game finished` записывает результат KGS; `Series: completed game 1` подтверждает, что он засчитан в запрошенную сумму. Затем он выходит из системы и выходит. По умолчанию поиск игры ограничен пятью минутами; используйте `--lobby-timeout 3600`, чтобы продлить время до часа.

## Основы настройки {#configuration-basics}

Всегда выбирайте файл явно с помощью `--config`. Клиент читает его один раз при запуске. Перезапустите, чтобы применить изменения, включая изменения в настройках перезапуска двигателя. Автоматический поиск файла конфигурации или перезагрузка в реальном времени отсутствуют.

Параметры командной строки переопределяют значения файла для этого запуска. Например:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
.\Kgs.Gtp.exe --config .\bot.toml --games 3 --undo-free Never
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
./Kgs.Gtp --config ./bot.toml --games 3 --undo-free Never
```

</details>

Имя пользователя начинается с `--username`, затем `account.username`, затем `KGS_USERNAME`. Не добавляйте в файл поле пароля: оно отклонено.

Используйте строки в кавычках для имен и вариантов выбора, целые числа для счетчиков и секунд, числа для коми и `true` или `false` для логических значений. Имена таблиц и ключей чувствительны к регистру. Неизвестные ключи и недопустимые значения останавливают запуск с помощью диагностики. Все значения продолжительности в этом руководстве указаны в секундах.

Относительный `engine.executable`, содержащий `/` или `\`, и относительный `account.clientIdFile` относятся к каталогу файла конфигурации. Простое имя исполняемого файла, например `katago`, использует поиск исполняемого файла. Аргументы механизма передаются без изменений, и механизм наследует рабочий каталог, из которого вы запускаете клиент. Используйте абсолютные пути для аргументов конфигурации модели и механизма, если вы запускаете из разных каталогов. Строки TOML, заключенные в одинарные кавычки, сохраняют обратную косую черту Windows. Строки не расширяют переменные среды.

### Аккаунт, сервер и движок {#account-server-and-engine}

| Настройка TOML | опция CLI | Значение и значение по умолчанию |
| --- | --- | --- |
| `account.username` | `--username` | KGS имя учетной записи; возвращается к `KGS_USERNAME`. |
| `account.clientIdFile` | `--client-id-file` | Постоянный идентификационный файл; обычно выбирается для каждого сервера и учетной записи. |
| `server.host` | `--host` | сервер KGS; по умолчанию `goserver.gokgs.com`. |
| `server.port` | `--port` | TCP-порт; по умолчанию `2379`, диапазон 1–65535. |
| `engine.executable` | `--engine` | Исполняемый файл движка для запуска. |
| `engine.arguments` | Аргументы после `--` | Массив аргументов механизма; по умолчанию пустой. |
| `engine.stdio` | `--stdio` | Используйте внешний подключенный движок вместо его запуска; по умолчанию `false`. |
| `engine.rules` | `--engine-rules` | Правила уже настроены в движке без `kgs-rules`. Нет декларации по умолчанию. |

Выберите исполняемый файл или `stdio = true`, но не оба одновременно. При стандартном вводе-выводе другая программа должна подключить stdin клиента к stdout механизма, а stdout клиента к stdin механизма. Для диагностики используйте stderr. Не указывайте аргументы механизма в этом режиме.

`engine.rules` принимает `Japanese`, `Chinese`, `Aga` или `NewZealand`. Это объявляет существующие правила движка; настроить сам движок в соответствии. Двигатели с `kgs-rules` автоматически получают правила выбранной игры.

Чтобы настроить полностью в командной строке, поместите аргументы механизма после `--`:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
.\Kgs.Gtp.exe --username YourBot --engine 'C:\Go\katago.exe' `
    --lobby Automatch --automatch-rank 20k --games 1 `
    -- gtp -config 'C:\Go\gtp.cfg' -model 'C:\Go\model.bin.gz'
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
./Kgs.Gtp --username YourBot --engine /opt/katago/katago \
    --lobby Automatch --automatch-rank 20k --games 1 \
    -- gtp -config /srv/go/gtp.cfg -model /srv/go/model.bin.gz
```

</details>

Явные аргументы механизма CLI заменяют весь массив файлов. Завершающий `--` без ничего после очистки этого массива. `--engine` и `--stdio` переопределяют выбор подключения к движку файла; `--stdio` также отбрасывает файловые аргументы. `--help` перечисляет все параметры, а `--version` печатает версию клиента.

## Выбор игр {#choosing-games}

Выберите один режим подбора игроков:

| `matchmaking.mode` / `--lobby` | Что делает бот |
| --- | --- |
| `Automatch` | Давайте KGS найдем соперника и выберем условия игры. |
| `Offer` | Рекламирует пользовательское испытание в указанной комнате. |
| `Join` | Ищет подходящее индивидуальное задание в указанной комнате. |

Без режима клиент входит в систему и ждет, пока его не остановят; он не находит игры. Один вызов играет одну игру за раз. Одновременные пользовательские испытания и автоматические матчи, участие в турнирах и ответы в чате в настоящее время не поддерживаются.

### Automatch {#automatch}

Используйте эти разделы вместе с настройками вашей учетной записи и движка:

```toml
[matchmaking]
mode = "Automatch"
gameType = "Free"
games = 0

[automatch]
speed = ["Fast", "Medium"]
rank = "20k"
opponents = "Humans"
maxRankDifference = 0
```

Опустите разделы `matchmaking.room`, `opponent`, `opponentPolicy`, `challengeNotes`, а также разделы `game` и `timing` в режиме Automatch. Это пользовательские настройки соревнования, и их нельзя комбинировать с автоматическим сопоставлением, даже если их значения соответствуют значениям по умолчанию.

| Настройка TOML | опция CLI | Варианты и значения по умолчанию |
| --- | --- | --- |
| `automatch.speed` | `--automatch-speed` | `All` (по умолчанию), `Blitz`, `Fast`, `Medium` или массив, например `["Fast", "Medium"]`. В комбинациях CLI используются запятые. |
| `automatch.rank` | `--automatch-rank` | Расчетное значение от `30k` до `1k`; требуется, если у учетной записи нет числового ранга сервера. |
| `automatch.opponents` | `--automatch-opponents` | `Humans` (по умолчанию), `Robots` или `Any`. |
| `automatch.maxRankDifference` | `--automatch-max-rank-difference` | По умолчанию `0`; диапазон 0–9 для Free, 0–6 для Ranked. |

Партии Automatch открытые, на доске 19×19, с японскими правилами и цветами, назначенными сервером. В равных партиях коми равно 6.5. При разрешённой разнице рангов возможно коми 0.5, а при разнице в два ранга и более — фиксированная расстановка форовых камней.

| Скорость | Основное время на игрока | Японское байоми |
| --- | --- | --- |
| `Blitz` | 60 секунд | 3 периоды 10 секунд |
| `Fast` | 600 секунд | 5 периоды 20 секунд |
| `Medium` | 1500 секунд | 5 периоды 30 секунд |

Движок должен поддерживать `final_status_list`, `kgs-time_settings` и `time_left`; для разрешения гандикапа также требуется `set_free_handicap`. Если в нем отсутствует `kgs-rules`, настройте его для японских правил и установите `engine.rules = "Japanese"`.

### Пользовательские испытания {#custom-challenges}

Замените разделы `matchmaking` и `automatch` файла примера настраиваемым профилем. В этом примере подходящим игрокам предлагается общедоступная игра 19×19 Free:

```toml
[matchmaking]
mode = "Offer"
gameType = "Free"
opponentPolicy = "Any"
room = "Computer Go"
games = 0
challengeNotes = "Computer player: 10-minute games"

[game]
boardSize = 19
rules = "Chinese"
komi = 7.5
color = "Nigiri"
handicap = 0
private = false

[timing]
system = "Absolute"
mainTime = 600
```

Используйте название комнаты, как показано в KGS. Имена могут содержать пробелы и символы, отличные от ASCII. Поиск использует точное совпадение без учета регистра после входа в систему и снова после повторного подключения. Отсутствующие или неоднозначные имена останавливают клиента при диагностике.

Для одного конкретного противника измените `opponentPolicy` на `"Named"` и добавьте `opponent = "OtherAccount"`. Для `Any` опустите `opponent`; подходящие открытые оппоненты подключены, зарегистрированы учетные записи, отличные от этого бота. Допускаются как люди, так и роботы.

Чтобы присоединиться к соревнованиям, используйте `mode = "Join"` и удалите `challengeNotes`. Все условия игры должны совпадать, включая правила, коми, гандикап, видимость и часы. Выберите собственный цвет бота: бот Offer, играющий черными, нуждается в боте Join, играющем белыми; для случайных цветов оба используют `"Nigiri"`. Измененные условия не принимаются молча.

| Настройка TOML | опция CLI | Варианты и значения по умолчанию |
| --- | --- | --- |
| `matchmaking.mode` | `--lobby` | `Offer`, `Join` или `Automatch`; нет режима по умолчанию. |
| `matchmaking.gameType` | `--game-type` | `Free` (по умолчанию) или `Ranked`. |
| `matchmaking.opponentPolicy` | `--opponent-policy` | `Named` (по умолчанию для пользовательских испытаний) или `Any`. |
| `matchmaking.opponent` | `--opponent` | Требуется для `Named`; имена учетных записей игнорируют регистр. |
| `matchmaking.room` | `--room` | Обязательное название комнаты для Offer и Join; например `"Computer Go"`. |
| `matchmaking.games` | `--games` | По умолчанию `1`; положительное число для серии, `0` для непрерывного воспроизведения. |
| `matchmaking.challengeNotes` | `--challenge-notes` | Только Offer; до символов 255, без управляющих символов. Пропуск приводит к появлению примечания оппонента. |

### Ranked игры {#ranked-games}

Установите `matchmaking.gameType = "Ranked"`, чтобы запрашивать исключительно игры Ranked. Учетная запись должна иметь предоставленное сервером разрешение `RankedRobot` и включенный ранг. Обратитесь за этим разрешением к администратору сервера KGS. Неустановленный ранг (`?`) разрешен, а отключенный ранг (`-`) — нет; для автоматического сопоставления по-прежнему требуется оценка, даже если учетная запись не имеет числового ранга.

Соперники Ranked должны иметь зарегистрированный аккаунт с включённым рангом — любительским или ещё не определённым. Ботам-соперникам также нужно разрешение `RankedRobot`. Пользовательские вызовы Ranked требуют открытой комнаты, открытой партии 19×19, не более шести форовых камней, коми от −10 до 10 и расчётного времени более 450 секунд на игрока. Расчёт включает дополнительное время; безлимитные партии также разрешены. Профиль Absolute на 600 секунд удовлетворяет ограничению. Клиент отклоняет неподходящие настройки и изменение сервером типа на Free.

## Пользовательские настройки игры {#custom-game-settings}

Эти настройки применяются к Offer и Join. Исключите их из конфигураций Automatch.

| Настройка TOML | опция CLI | Варианты и значения по умолчанию |
| --- | --- | --- |
| `game.boardSize` | `--board-size` | По умолчанию `9`; диапазон 2–25 при условии поддержки двигателя. |
| `game.rules` | `--rules` | `Chinese` (по умолчанию), `Japanese`, `Aga` или `NewZealand`. |
| `game.komi` | `--komi` | По умолчанию `7.5`; от −100 до 100 с шагом в полпункта. |
| `game.color` | `--color` | `Black`, `White` или `Nigiri`; по умолчанию черный для Offer и белый для Join. |
| `game.handicap` | `--handicap` | По умолчанию `0`; в противном случае 2–9 находится в пределах ограничений на размещение на доске. Невозможно объединить с Нигири. |
| `game.private` | `--private` | По умолчанию `false`; требуется приватная игра, сохраняя при этом объявление о вызове в выбранной комнате. |

Фора не изменяет коми автоматически: задавайте оба значения явно. Японские правила и AGA используют фиксированную расстановку: доска не менее 7×7, на 7×7 или доске с чётной длиной стороны — не более четырёх камней. Китайские и новозеландские правила используют свободную расстановку: не более девяти камней и хотя бы один свободный пункт. Для форовых партий требуется `set_free_handicap`, а чёрным при свободной расстановке также нужен `place_free_handicap`.

### Контроль времени {#time-controls}

| Настройка TOML | опция CLI | По умолчанию и диапазон |
| --- | --- | --- |
| `timing.system` | `--time-system` | `Absolute` (по умолчанию), `None`, `Canadian` или `ByoYomi`. |
| `timing.mainTime` | `--main-time` | По умолчанию `600` или `0` для «Нет»; диапазон 0–86400. |
| `timing.byoYomiTime` | `--byo-yomi-time` | По умолчанию `0`; 1–86400 за японский период или канадский блок при использовании сверхурочной работы. |
| `timing.byoYomiPeriods` | `--byo-yomi-periods` | По умолчанию `0`; 1–255 для БёЁми. |
| `timing.canadianStones` | `--canadian-stones` | По умолчанию `0`; 1–255 для Канады. |

Для японской сверхурочной работы с десятью минутами основного времени и пятью периодами 30-секунд:

```toml
[timing]
system = "ByoYomi"
mainTime = 600
byoYomiTime = 30
byoYomiPeriods = 5
```

Для канадского сверхурочного времени используйте `system = "Canadian"`, `byoYomiTime` для секунд на блок и `canadianStones` для камней на блок. Опустите `byoYomiPeriods`. Сверхурочная работа допускает нулевое основное время. Абсолют требует положительного основного времени и отсутствия дополнительных часов; None требует, чтобы все явно заданные значения времени были равны нулю. Общий резерв часов также должен соответствовать диапазону сервера; сообщается о недопустимых комбинациях.

Для игр на время требуются `time_left` и `time_settings` или `kgs-time_settings`. В Японии сверхурочная работа требует наличия `kgs-time_settings`. Безлимитные игры не требуют команд часов. Таймауты ответа движка отделены от игровых часов и не дают боту больше игрового времени.

## Запуск бота {#running-the-bot}

Установите `matchmaking.games` на положительную сумму или на `0`, чтобы продолжить игру. Учитываются только результаты, подтвержденные KGS. После завершенной игры клиент покидает ее и использует исходные настройки подбора игроков для следующей игры. Неудачная или незавершенная игра останавливает серию и не считается завершенной.

Для непрерывной игры с более длительным перерывом между играми:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
.\Kgs.Gtp.exe --config .\bot.toml --games 0 --lobby-timeout 3600
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
./Kgs.Gtp --config ./bot.toml --games 0 --lobby-timeout 3600
```

</details>

Нажмите Ctrl+C, чтобы остановить. Клиент выходит из системы, просит движок выйти и при необходимости останавливает запущенный движок. Остановка во время игры не определяет окончательный результат. Осмотрите любую незавершенную игру, прежде чем начинать новый запуск.

### Журналы и коды выхода {#logs-and-exit-codes}

Состояние, ошибки, справка и диагностика двигателя доступны по адресу stderr. Чтобы сохранить их:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
.\Kgs.Gtp.exe --config .\bot.toml 2> .\bot.log
$LASTEXITCODE
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
./Kgs.Gtp --config ./bot.toml 2> ./bot.log
echo $?
```

</details>

Используйте диспетчер сервисов или внешние инструменты для ротации журналов. В стандартном режиме ввода-вывода оставьте stdout подключенным к двигателю; он содержит команды GTP.

| Код выхода | Значение |
| --- | --- |
| `0` | Запрошенные игры завершены, или команда зонда/справки/версии выполнена успешно. |
| `1` | Сбой конфигурации или выполнения; осмотрите диагностику. |
| `130` | Оператор отмены, включая Ctrl+C. |

### Постоянное состояние и существующие игры {#persistent-state-and-existing-games}

Клиент сохраняет удостоверение, назначенное KGS. В режимах подбора игроков файл по умолчанию находится в локальном каталоге данных приложения .NET по адресу `Kgs.Gtp/identities/<server-and-account-hash>`. На Windows это значение обычно ниже `%LOCALAPPDATA%`. Чтобы выбрать стабильное место для записи, установите `account.clientIdFile = "./state/client-id"`. Сохраните его при обновлении и замене контейнера. Используйте отдельный файл для каждого сервера и учетной записи.

Offer и Join сначала проверяют выбранную комнату на наличие незавершенной игры, принадлежащей этому аккаунту. Возобновить можно только одну совместимую игру; его оппонент и полный профиль должны совпадать. Несколько или несовпадающие игры прекращают запуск. Архивные игры не загружаются автоматически.

Запущенный сеанс автоматического сопоставления может восстановить назначенную ему игру после потери соединения. Новый процесс не обнаруживает автоматически старые игры автоматического сопоставления. Решите незавершенную игру с автоматическим совпадением, прежде чем снова зарегистрироваться.

### Откаты, паузы и отсутствие соперника {#takebacks-pauses-and-opponent-absence}

`undo.free` / `--undo-free` и `undo.ranked` / `--undo-ranked` независимо принимают `Never` (по умолчанию) или `Allow`. Пример разрешает отмену ходов в Free и запрещает её в Ranked. Allow удовлетворяет разрешённые сервером запросы соперника во время обычной активной игры; сам бот отмены не запрашивает. Затем он воспроизводит подтверждённую историю, поэтому поддержка GTP `undo` движком не требуется. Возобновление игры из-за спора о подсчёте регулируется отдельно.

KGS управляет паузами, отсрочкой и возобновлением. Во время паузы или отсрочки бот не начинает новый игровой процесс или действия по подсчету очков. Каждая непрерывная пауза, отсрочка и отсутствие оппонента имеют отдельный лимит, по умолчанию равный 300 секунд:

| Настройка TOML в `[interactions]` | опция CLI |
| --- | --- |
| `pauseTimeoutFree` | `--pause-timeout-free` |
| `adjournmentTimeoutFree` | `--adjournment-timeout-free` |
| `opponentTimeoutFree` | `--opponent-timeout-free` |
| `pauseTimeoutRanked` | `--pause-timeout-ranked` |
| `adjournmentTimeoutRanked` | `--adjournment-timeout-ranked` |
| `opponentTimeoutRanked` | `--opponent-timeout-ranked` |

Каждый принимает 1–86400 секунд. По истечении срока действия клиент с кодом 1 останавливается и игра остается незавершенной; он не сдается и не начинает новую игру. Повторное подключение и замена двигателя не сбрасывают эти ожидания. Другие активные сроки могут истечь раньше. Пока оппонент отсутствует, бот все равно может двигаться, если KGS разрешает это.

## Таймауты и восстановление {#timeouts-and-recovery}

### Обычные таймауты {#normal-timeouts}

Все принимают 1–86400 секунд:

| Настройка TOML | опция CLI | По умолчанию | Пределы |
| --- | --- | --- | --- |
| `timeouts.login` | `--login-timeout` | `30` | Подключение и вход. |
| `timeouts.lobby` | `--lobby-timeout` | `300` | Согласование одного запроса или автоматическая регистрация; также ограничивает поиск по названию комнаты. |
| `timeouts.move` | `--move-timeout` | `600` | Один нормальный поиск или очистка движка. |
| `timeouts.scoring` | `--scoring-timeout` | `120` | Один раунд подсчета очков, включая оценку и согласование. |
| `timeouts.cleanup` | `--cleanup-timeout` | `300` | Все попытки очистки и последующий подсчет очков объединяются. |

### KGS потеря соединения {#kgs-connection-loss}

Клиент повторяет попытки транспорта, снова проходит аутентификацию и снова присоединяется к прерванной игре, используя историю сервера. Он не отправляет повторно неопределенный ход и не заменяет известную прерванную игру новым испытанием. Отклоненный вход в систему, выход из системы, неверные данные сервера, незаконные перемещения механизма и отклоненные команды механизма являются сбоями терминала.

| Настройка TOML | опция CLI | По умолчанию и диапазон |
| --- | --- | --- |
| `connectionRecovery.attempts` | `--reconnect-attempts` | Дополнительное ограничение на одно отключение; 0–100. Опущено по умолчанию; ноль отключает повторные попытки. |
| `connectionRecovery.delay` | `--reconnect-delay` | `1` — второе начальное окно; 0–30, удваивающийся до 30-секундного ограничения, с полным джиттером. |
| `connectionRecovery.timeout` | `--recovery-timeout` | `120` секунд за переподключение через переподключение игры; 1–86400. |
| `connectionRecovery.budget` | `--recovery-budget` | Всего `180` секунд за один сбой, включая слив, отсрочку, вход в систему и повторное присоединение; 1–86400. |
| `connectionRecovery.resetAfter` | `--recovery-reset-after` | `60` работоспособных секунд после повторного подключения перед сбросом бюджета и счетчиком повторных попыток; 1–86400. |
| `connectionRecovery.engineDrainTimeout` | `--engine-drain-timeout` | `30` секунд, чтобы завершить и отказаться от старых работ по двигателю; 1–86400. |

Бюджет простоя начинается при обнаружении потери соединения. Каждое повторное подключение ограничено оставшимся бюджетом, а также собственным временем ожидания входа/повторного подключения. Каждая задержка выбирается случайным образом в диапазоне от нуля до максимального значения, которое удваивается от 1 секунды до ограничения 30 секунды. Восстановление прекращается, когда исчерпан общий бюджет или явно установленное ограничение попыток.

После повторного подключения бот может продолжать играть после истечения старого срока восстановления. Более позднее отключение получает новый бюджет после 60 здоровых секунд. При отключении до этого интервала сохраняется предыдущий крайний срок и количество повторных попыток, включая время кратковременного подключения. Вход в систему сам по себе не обеспечивает работоспособность, если в игру все еще необходимо повторно войти.

### Отказ двигателя {#engine-failure}

Если работающий механизм завершает работу или его поток становится непригодным для использования, клиент сохраняет сеанс KGS активным и пытается запустить замену, используя исходный исполняемый файл и аргументы. Прежде чем продолжить, он проверяет замену и воспроизводит подтвержденную историю. Сбои при первоначальном запуске/обнаружении механизма останавливают работу клиента. Часы KGS продолжаются, пока механизм недоступен.

| Настройка TOML | опция CLI | По умолчанию и диапазон |
| --- | --- | --- |
| `engineRecovery.attempts` | `--engine-restart-attempts` | `3` автоматические замены при вызове; 0–100. Зеро ждет восстановления оператора. |
| `engineRecovery.delay` | `--engine-restart-delay` | `1` — второе начальное окно; 0–30, удваивающийся до 30-секундного ограничения, с полным джиттером. |
| `engineRecovery.timeout` | `--engine-recovery-timeout` | `120` секунд для обнаружения/настройки и отдельно для воспроизведения; 1–86400. |
| `engineRecovery.pipe` | `--engine-recovery-pipe` | Местная труба рекуперации; по умолчанию `kgs-gtp-<process ID>`. Используйте 1–100 буквы ASCII, цифры, точки, дефисы или символы подчеркивания. |

Когда автоматические замены исчерпаны, диагностика называет локальный канал восстановления. Бот ожидает вмешательства оператора, пока продолжаются обычные сроки игры и лобби. Чтобы перезапустить механизм, запущенный клиентом, подключитесь от имени того же пользователя операционной системы и отправьте UTF-8 `restart`, а затем LF. Например, если вы настроили `pipe = "YourBot-recovery"`, запустите это в другом терминале после ожидания диагностики:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
$pipe = [IO.Pipes.NamedPipeClientStream]::new(
    '.', 'YourBot-recovery', [IO.Pipes.PipeDirection]::InOut)
try {
    $pipe.Connect(5000)
    $request = [Text.Encoding]::UTF8.GetBytes("restart`n")
    $pipe.Write($request, 0, $request.Length)
    $pipe.Flush()
}
finally { $pipe.Dispose() }
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
python3 - <<'PY'
import os
import socket

pipe = os.path.join(os.environ.get("TMPDIR") or "/tmp", "CoreFxPipe_YourBot-recovery")
with socket.socket(socket.AF_UNIX, socket.SOCK_STREAM) as connection:
    connection.settimeout(5)
    connection.connect(pipe)
    connection.sendall(b"restart\n")
PY
```

</details>

Для примера Linux требуется Python 3, и он подключается к сокету Unix-домена .NET. Запустите его от того же пользователя, с тем же `TMPDIR`, что и у бота (по умолчанию — `/tmp`). Замените `YourBot-recovery` на настроенное имя канала; служба с частным временным каталогом также требует, чтобы клиент работал внутри той же среды.

Успешная замена оператора запускает новый бюджет автоматических повторов. Редактирование файла TOML не приводит к изменению исполняемого файла или аргументов работающего клиента.

Для `--stdio` внешний диспетчер должен подключить новый двигатель через дуплексную трубу восстановления и реле GTP в обоих направлениях. В этом режиме приветствие `restart` отсутствует. Исходное соединение stdin/stdout не может быть повторно использовано после сбоя.

## Устранение неполадок {#troubleshooting}

| Симптом | Что проверить |
| --- | --- |
| Ошибка конфигурации перед запуском двигателя | Проверьте указанный файл и расположение источника, точное написание ключа, имена комнат в кавычках и типы значений TOML. Устаревшие файлы свойств Java требуют преобразования. |
| Двигатель не может запуститься или открыть свою модель | Проверьте пути к исполняемым файлам и аргументам, аргументы режима GTP и рабочий каталог. Попробуйте `--probe`. |
| Отсутствуют команды GTP или неверная версия протокола. | Используйте полный движок GTP v2. Для обнаружения требуются `protocol_version`, `name`, `version`, `known_command`, `list_commands`, `quit`, `boardsize`, `clear_board`, `komi`, `play` и `genmove`. |
| Проверка правил, времени или подсчета очков не удалась | Проверьте возможности движка для выбранного профиля. Объявляйте `engine.rules` только в том случае, если в движке отсутствует `kgs-rules`, и совпадайте с его фактической конфигурацией. Для всех автоматических игр требуется `final_status_list`. |
| Ошибка входа | Проверьте имя учетной записи `KGS_PASSWORD` в среде запуска, адрес сервера и указанную причину отклонения. |
| Комната не найдена | Скопируйте его полное имя из KGS на выбранном сервере. При сопоставлении регистр игнорируется, но требуется полное имя. |
| Ожидание тайм-аута игры или лобби | Проверьте соответствие условий, правомочность оппонента, название комнаты и настройки автоматического соответствия. Увеличьте `timeouts.lobby`, если предполагается более длительное ожидание. |
| Запись Ranked отклонена | Проверьте разрешение RankedRobot, включенный ранг, общественную комнату и ограничения профиля Ranked. |
| Подсчет очков прекращается при разногласиях | Споры Японии не имеют поддержки. Для очистки китайского языка, AGA и Новой Зеландии требуется `kgs-genmove_cleanup`; повторяющиеся споры, отсутствие прогресса и истечение срока очистки останавливают клиента. |
| Бот останавливается после паузы или ухода оппонента | Просмотрите соответствующий тайм-аут взаимодействия и проверьте незавершенную игру перед перезапуском. |
| Движок недоступен, но аккаунт все еще онлайн | Проверьте диагностику двигателя и сообщение канала восстановления. Автоматические повторные попытки могут быть исчерпаны; игровые часы и сроки все еще действуют. |
| Ошибка файла личных данных | Убедитесь, что настроенное расположение состояния доступно для записи и содержит созданный клиентом файл идентификации. |

Сообщая о проблеме, укажите версию клиента, название/версию движка, идентификатор игры, если он доступен, соответствующие настройки и диагностику stderr. Опустить пароли.
