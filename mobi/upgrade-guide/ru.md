В этом руководстве бот перемещается с `kgsGtp.jar` и его конфигурации Java `.properties` на Mobi и TOML. Старый файл невозможно загрузить напрямую; автоматического импортера нет. Сохраните его для справки при создании нового файла. См. [руководство пользователя]({% include page-url.html key='mobi/user-guide' %}) для нормальной работы и полный справочник по настройкам.

В этом руководстве рассматриваются Windows и Linux. Разверните раздел вашей операционной системы, чтобы увидеть команды PowerShell или Bash. Запустите команды из извлеченного каталога клиента.

## Этапы обновления {#upgrade-steps}

1. Завершите или разрешите любую текущую игру, затем остановите старый клиент и его движок.    Отключите его автоматический перезапуск при попытке замены, чтобы оба клиента не входили в систему под одной учетной записью.
2. Извлеките пакет моста Mobi GTP для вашей архитектуры Windows или Linux.    Пакет включает среду выполнения .NET. Сохраните свой двигатель, модель и конфигурацию двигателя; они остаются отдельными от клиента.
3. Скопируйте [bot.example.toml]({{ '/mobi/bot.example.toml' | relative_url }}) в `bot.toml`. Переместите настройки, используя таблицы ниже. Введите пароль в `KGS_PASSWORD` и явно выберите тип игры, политику возврата и количество игр.
4. Проверьте двигатель с помощью команд ниже. Исправьте ошибки обнаружения движка перед входом в систему. Дополнительные проверки возможностей игры запускаются при обычном запуске.
5. Запустите одну игру Free с помощью `--games 1`. Проверьте логин, выбор соперника, часы, подсчет очков и диагностику `Series: completed game 1`.
6. Установите `games = 0`, если вы хотите непрерывную игру, а затем обновите программу запуска или службу, чтобы использовать новый исполняемый файл, путь конфигурации, среду паролей и журналы.

Скопируйте шаблон, затем отредактируйте учетную запись, пути к движку и настройки игры:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
Copy-Item .\bot.example.toml .\bot.toml
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
cp ./bot.example.toml ./bot.toml
chmod +x ./Kgs.Gtp
```

</details>

После редактирования проверьте обнаружение движка без входа в систему:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
.\Kgs.Gtp.exe --config .\bot.toml --probe
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
./Kgs.Gtp --config ./bot.toml --probe
```

</details>

Чтобы вернуться к старому клиенту, сначала остановите новый клиент и движок, проверьте все незавершенные игры и восстановите исходную программу запуска и файл свойств. Сохраните файл идентификации нового клиента для последующего возврата в Mobi.

## Изменения, которые необходимо просмотреть перед переходом {#changes-to-review-before-switching}

| Площадь | Старый клиент | Mobi |
| --- | --- | --- |
| Запуск | `java -jar kgsGtp.jar bot.properties key=value` | `Kgs.Gtp --config bot.toml --option value`; Исполняемый файл Windows заканчивается на `.exe`. |
| Конфигурация | Свойства Java, включая escape-последовательности Java | UTF-8 TOML с именованными разделами, строками в кавычках, числами, массивами и логическими значениями. Неизвестные ключи являются ошибками. |
| Режим по умолчанию | Automatch | Никакого подбора игроков, если не выбран `matchmaking.mode` или `--lobby`. |
| Количество игр | Продолжает искать игры | По умолчанию встроена одна завершенная игра. Установите `games = 0` для непрерывной игры; приведенный пример уже делает это. |
| Тип игры | Automatch может разрешить Free и Ranked вместе | Выберите исключительно `Free` (по умолчанию) или `Ranked`. Не существует смешанных настроек или резервного варианта. |
| Комната | Название комнаты | Название комнаты, все еще строка; используйте `room = "English Room"`. Поиск игнорирует регистр и требует точного имени. |
| Пользовательские условия игры | Игроки могут предлагать изменения | Настроенные условия должны точно совпадать, включая цвета, коми, гандикап, видимость и контроль времени. |
| Возвраты | Обычно разрешено в играх Free, запрещено в Ranked. | Обе встроенные политики по умолчанию имеют значение `Never`. Установите `undo.free = "Allow"`, чтобы сохранить обычное поведение Free. Пример делает это. |
| Гандикап Automatch | Можно было бы разрешить до девяти рангов, если бы движок поддерживал гандикап. | `maxRankDifference` по умолчанию равен `0`; выберите его явно, не более 9 для Free или 6 для Ranked. |
| Повторные попытки подключения | `reconnect=t` позволяет продолжать повторные попытки. | Бюджет простоя по умолчанию 180-секунды, экспоненциальная задержка с джиттером и сброс после 60 работоспособных секунд. |
| Отказ двигателя | Нет автоматического перезапуска двигателя от `reconnect` | Отдельный бюджет автоматического перезапуска; истощение ожидает восстановления оператора, пока продолжаются обычные сроки. |
| Уход противника | Может вернуться к матчмейкингу после лимита отсутствия | Новый клиент останавливается с диагностикой незавершенной игры по истечении настроенного ожидания. |

Пример представляет собой стартовую конфигурацию, а не утверждение о сохранении всего старого поведения. В частности, решите, должна ли эта учетная запись играть в Free или Ranked, прежде чем включать непрерывную работу.

## Сопоставьте старые настройки {#map-the-old-settings}

В новых именах настроек ниже используется нотация `section.key`. Например, `account.username` означает `username = "YourBot"` под `[account]`.

### Аккаунт, подключение и движок {#account-connection-and-engine}

| Старая недвижимость | Новая настройка | Примечания по миграции |
| --- | --- | --- |
| `name` | `account.username` / `--username` | `KGS_USERNAME` также поддерживается, если имя пользователя не настроено. |
| `password` | Переменная среды `KGS_PASSWORD` | Удалите его из новой конфигурации; Поля пароля и параметры CLI пароля не поддерживаются. |
| `server.host` | `server.host` / `--host` | Строка; по умолчанию `goserver.gokgs.com`. |
| `server.port` | `server.port` / `--port` | Целое число; по умолчанию `2379`. |
| `reconnect=f` | `connectionRecovery.attempts = 0` | Отключает повторные попытки транспорта KGS; восстановление двигателя настраивается отдельно. |
| `reconnect=t` | `[connectionRecovery]` | Выберите временной бюджет на каждый сбой; значение по умолчанию — 180 секунд. Ограничение попыток не является обязательным. |
| `engine` | `engine.executable` и `engine.arguments` | Разделите команду на исполняемый файл и отдельные аргументы; см. ниже. |
| Нет свойств подключения двигателя | `engine.stdio = true` / `--stdio` | Стандартный ввод-вывод теперь должен выбираться явно. |
| `gtp.in`, `gtp.out` | Нет прямой настройки | Внешняя пусковая установка может соединить два направления через `--stdio`. Клиент не открывает именованные файлы или FIFO из конфигурации. |
| `engine.port` | Нет прямой настройки | Нет прослушивателя TCP механизма. Используйте внешний адаптер с `--stdio` или позвольте клиенту запустить движок. |
| `logFile` | Захват stderr снаружи | Используйте перенаправление оболочки или диспетчер служб; встроенные имена и ротация журналов Java не переносятся. |
| `verbose` | Нет прямой настройки | Обычная диагностика переходит к stderr; эквивалентного полного переключателя регистрации трафика GTP/сервера не существует. |

Локальный `engineRecovery.pipe` предназначен для замены вышедшего из строя механизма во время работающего сеанса. Он не заменяет старые настройки запуска `engine.port`, `gtp.in` или `gtp.out`.

### Матчмейкинг и настройки игры {#matchmaking-and-game-settings}

| Старая недвижимость | Новая настройка | Примечания по миграции |
| --- | --- | --- |
| `mode=auto` | `matchmaking.mode = "Automatch"` | Опустите комнату, пользовательские настройки оппонента и разделы `game`/`timing`. |
| `mode=custom` | `matchmaking.mode = "Offer"` | Добавьте `opponentPolicy = "Any"` для открытых испытаний или `"Named"` плюс `opponent`. |
| `mode=wait` | `matchmaking.mode = "Join"` | Задайте имя комнаты и `opponent`; предлагаемый профиль должен точно совпадать. |
| `mode=both` | Нет комбинированного режима | Для этого вызова выберите Automatch, Offer или Join. |
| `mode=tournament` | Не поддерживается | Участие в турнире не реализовано; сохраните старый клиент, если это необходимо. |
| `room` | `matchmaking.room` / `--room` | Сохраните имя комнаты в виде строки в кавычках. Требуется для Offer и Join; опустите для Automatch. По умолчанию не существует последней использованной комнаты. |
| `opponent` | `matchmaking.opponent` | Для индивидуальных задач используйте `opponentPolicy = "Named"`. Опустите обе пользовательские настройки противника для Automatch. |
| `gameNotes` | `matchmaking.challengeNotes` | Только Offer; не более символов 255 без управляющих символов. |
| `rules` | `game.rules` | Используйте `Japanese`, `Chinese`, `Aga` или `NewZealand`. Устанавливает точные пользовательские условия игры. |
| `komi` | `game.komi` | Число, а не строка в кавычках; устанавливается явно, в том числе и для игр с гандикапом. |
| `rules.boardSize` | `game.boardSize` | Целое число. Установите явно: значение по умолчанию для новой пользовательской игры — 9. |
| `rules.time` | `[timing]` | Разделите поля на системные, секундные и сверхурочные, используя примеры ниже. |
| `automatch.speed` | `automatch.speed` | Например, `speed = ["Blitz", "Medium"]` или `"All"`. В комбинациях CLI используются запятые. |
| `automatch.rank` | `automatch.rank` | Котируются с `30k` по `1k`; по-прежнему требуется, если числовой ранг сервера отсутствует. |
| `undo=f` | `[undo]` с `free = "Never"`, `ranked = "Never"` | Это также встроенные значения по умолчанию. |
| `undo=t` или опущено | `[undo]` с `free = "Allow"`, `ranked = "Never"` | Сохраняет обычное старое различие Free/Ranked. При желании новые возвраты Ranked можно включить отдельно. |
| `talk` | Не поддерживается | Ответы в приватном чате и переадресация в чате не реализованы. |
| `hint.cleanup`, `hint.noArguing` | Не поддерживается | Нет настраиваемых подсказок в чате для оценки споров. |

`game.rules` и `engine.rules` имеют разные цели. Первый выбирает собственные правила игры. Последний объявляет правила, уже настроенные в движке, в котором отсутствует `kgs-rules`; это не меняет конфигурацию этого двигателя.

### Разделить команду двигателя {#split-the-engine-command}

Старая недвижимость может быть:

```properties
engine=/opt/katago/katago gtp -config /srv/go/gtp.cfg -model /srv/go/model.bin.gz
```

Новая конфигурация:

```toml
[engine]
executable = "/opt/katago/katago"
arguments = ["gtp", "-config", "/srv/go/gtp.cfg", "-model", "/srv/go/model.bin.gz"]
```

Не помещайте всю командную строку в `executable`. Оценки оболочки нет. Каждый аргумент представляет собой один элемент массива, включая пути, содержащие пробелы. Для Windows строки TOML в одинарных кавычках сохраняют буквальную обратную косую черту:

```toml
[engine]
executable = 'C:\Go Engines\katago.exe'
arguments = ["gtp", "-config", 'C:\Go Engines\gtp.cfg', "-model", 'C:\Go Engines\model.bin.gz']
```

Замените escape-символы свойств Java фактическим текстом в UTF-8 TOML. Относительные пути к исполняемым файлам, содержащие разделитель, разрешаются из каталога TOML; Пути аргументов остаются относительными к рабочему каталогу запуска. Абсолютные пути модели и конфигурации упрощают воспроизведение запуска служб.

### Преобразование контроля времени {#convert-time-controls}

Используйте только один из этих разделов `[timing]` и только с Offer или Join.

Старый `rules.time=0`:

```toml
[timing]
system = "None"
mainTime = 0
```

Старый `rules.time=30:00`:

```toml
[timing]
system = "Absolute"
mainTime = 1800
```

Старый `rules.time=30:00+5x0:30`:

```toml
[timing]
system = "ByoYomi"
mainTime = 1800
byoYomiTime = 30
byoYomiPeriods = 5
```

Старый `rules.time=30:00+25/10:00`:

```toml
[timing]
system = "Canadian"
mainTime = 1800
byoYomiTime = 600
canadianStones = 25
```

Все новые значения времени представляют собой целые секунды. Удалите поля сверхурочной работы, принадлежащие другой системе. Для сверхурочной работы в Японии требуется команда двигателя `kgs-time_settings`; он не аппроксимируется с использованием другой системы часов.

## Пример: перенос бота автоматического сопоставления {#example-migrate-an-automatch-bot}

Предположим, что соответствующие части старого файла:

```properties
name=YourBot
password=<account password>
mode=auto
room=English Room
automatch.speed=fast,medium
automatch.rank=20k
undo=t
reconnect=t
engine=/opt/katago/katago gtp -config /srv/go/gtp.cfg -model /srv/go/model.bin.gz
```

Создайте этот `bot.toml` для начальной игры Free. Automatch не принимает настройки помещения, поэтому старое свойство `room` опущено:

```toml
[account]
username = "YourBot"
clientIdFile = "./state/client-id"

[engine]
executable = "/opt/katago/katago"
arguments = ["gtp", "-config", "/srv/go/gtp.cfg", "-model", "/srv/go/model.bin.gz"]

[matchmaking]
mode = "Automatch"
gameType = "Free"
games = 1

[automatch]
speed = ["Fast", "Medium"]
rank = "20k"
opponents = "Humans"
maxRankDifference = 0

[undo]
free = "Allow"
ranked = "Never"

[connectionRecovery]
budget = 180
resetAfter = 60
```

Для Windows замените пути `[engine]` на пример Windows в [Разделить команду двигателя](#split-the-engine-command). Установите пароль и запустите одну игру:

<details markdown="1">
<summary>Windows (PowerShell)</summary>

```powershell
$env:KGS_PASSWORD = '<account password>'
.\Kgs.Gtp.exe --config .\bot.toml --games 1
```

</details>

<details markdown="1">
<summary>Linux (Bash)</summary>

```bash
read -r -s -p 'KGS password: ' KGS_PASSWORD
export KGS_PASSWORD
printf '\n'
./Kgs.Gtp --config ./bot.toml --games 1
```

</details>

В этом примере намеренно выбраны даже игры Free. Чтобы сохранить соответствие гандикапу, выберите подходящий `maxRankDifference` и проверьте поддержку двигателя. Чтобы сыграть в Ranked, выберите `gameType = "Ranked"`, проверьте разрешение RankedRobot учетной записи и включенный ранг, а также используйте не более шести рангов разницы. Один вызов не может принять оба типа игры.

Для пользовательского бота используйте [пример пользовательского задания]({% include page-url.html key='mobi/user-guide' %}#custom-challenges), скопируйте старое название комнаты и явно перенесите размер доски, правила, коми, цвет, гандикап и преобразованные настройки времени.

## Совместимость двигателя и автоматическая работа {#engine-compatibility-and-unattended-operation}

Для Mobi требуется GTP v2 и полный обязательный набор команд. Здесь требуются некоторые команды, которые старый клиент считал необязательными. Для всех автоматических игр также требуется `final_status_list`. Для игр с таймером требуется `time_left` и поддерживаемая команда синхронизации. Проверьте требования к движку в руководстве пользователя для выбранного профиля; старая рабочая конфигурация сама по себе не обеспечивает совместимости.

Обычное японское соглашение о подсчете очков поддерживается, но неразрешенные японские споры останавливают игру. Для очистки Китая, AGA и Новой Зеландии требуется `kgs-genmove_cleanup`, имеются ограниченные попытки и общий срок. Не существует резервного варианта старого клиента, который позволял бы противнику определять все мертвые камни, когда автоматический подсчет очков недоступен.

Прежде чем оставлять бота без присмотра, просмотрите эти настройки сервиса:

- Явно установите `games = 0`, если он должен продолжать воспроизведение. Каждая попытка лоббирования по-прежнему имеет срок по умолчанию 300 – секунды; при необходимости увеличьте `timeouts.lobby`.
- Настройте повторные попытки подключения KGS и перезапуск двигателя отдельно. Для восстановления KGS по умолчанию используется значение 180 секунд на каждый сбой и сбрасывается после 60 секунд работоспособности. Восстановление двигателя допускает три автоматические замены за один раз; истощение может оставить активный сеанс KGS в ожидании восстановления оператора.
- Выберите паузу, отсрочку и лимиты отсутствия оппонентов. По умолчанию для каждого из них установлено значение 300 секунд; истечение срока действия останавливает клиент без подсчета или отказа от незавершенной игры.
- Сохраните файл идентификации клиента в доступном для записи каталоге состояния. Новый процесс не обнаруживает автоматически старые игры автоматического сопоставления.
- Захватите stderr и настройте внешнее хранение журналов. Выход 0 означает нормальное завершение, 1 указывает на сбой, а 130 указывает на отмену.

В [руководстве пользователя]({% include page-url.html key='mobi/user-guide' %}#timeouts-and-recovery) подробно описаны настройки тайм-аута, восстановление соединения и восстановление механизма оператора.
